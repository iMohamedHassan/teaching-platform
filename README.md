# منصة تعليمية متعددة المدرسين — المرحلة 1

Express + Mongoose + HTML/CSS/JS (واجهة عربي RTL، وضع فاتح/داكن).
الاسم الحالي «منصتي» مؤقت: غيّره من `BRAND_NAME` في `.env` وهيتغير في كل الصفحات.

## التشغيل محلياً

```bash
npm install
cp .env.example .env        # عدّل MONGODB_URI و JWT_ACCESS_SECRET و ADMIN_*
npm run seed                # بيعمل السوبر أدمن
npm run seed:demo           # (اختياري) مستر محمد سعد (ماث) + مستر أحمد كمال (تاريخ) بباقة وكورس لكل واحد
npm run dev                 # http://localhost:3000
```

ولّد مفتاح JWT قوي: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`

| الدور | يعمل إيه |
|---|---|
| `super_admin` | كل حاجة: مدرسين، مستخدمين، باقات وأسعار، اشتراكات، سجل العمليات |
| `teacher` | كورسات ومحاضرات وواجبات **مدرسه بس** (إضافة/تعديل/حذف) + يشوف طلابه وباقاته |

## إزاي الحاجات بتشتغل

- **المدرس:** من الأدمن > المدرسين > إضافة. بيتعمل ملفه + حساب دخول له في خطوة واحدة.
- **المحتوى:** مدرس ← كورسات (مثلاً «محاضرات أكتوبر 2026/2027») ← محاضرات (رابط يوتيوب Unlisted) + واجبات.
- **الباقة:** مدرس + سنة + سعر + مدة بالأيام (فاضي = بدون انتهاء) + الكورسات اللي جواها.
- **الاشتراك (دلوقتي يدوي):** الأدمن > الاشتراكات > تفعيل اشتراك برقم الطالب. الدفع الأوتوماتيك والأكواد في المرحلة 3.
- **زرار «اطلب الاشتراك» في صفحة المدرس** بيفتح واتساب برقم `WHATSAPP_NUMBER` ورسالة جاهزة.
- **حذف الباقة** ممنوع لو فيها مشتركين (عطّلها بدل الحذف). **حذف المدرس** نهائي ويمسح كل محتواه، ويطلب تكتب الـ slug للتأكيد.

## الأمان المتطبق

- كلمات السر: bcrypt. الدخول بـ JWT قصير (15 دقيقة) + refresh token بيتغير مع كل تجديد، الاتنين في `httpOnly` cookies. الـ refresh متخزن مشفّر (SHA-256) في الداتا بيز.
- قفل الحساب بعد 5 محاولات غلط لمدة 15 دقيقة (قابل للتعديل في `.env`) + منع كشف هل الرقم موجود ولا لأ.
- حد أقصى جهازين للطالب (الأدمن يقدر يصفّرها)، وتسجيل الخروج من كل الأجهزة.
- Rate limiting: عام على الـ API، وأشد على الدخول والتسجيل والعمليات الحساسة.
- `helmet` + CSP (من غير inline scripts)، وCORS مضبوط، و`express-mongo-sanitize`، و`hpp`، وحدود حجم الطلب، والتحقق من كل input بـ Zod (والحقول غير المعرّفة بتتشال).
- حماية CSRF: هيدر `X-Requested-With` إجباري + فحص `Origin` على أي طلب بيغيّر بيانات.
- RBAC في السيرفر + نطاق المدرس: المدرس مايقدرش يقرأ أو يعدّل أو يحذف حاجة تخص مدرس تاني حتى لو عرف الـ ID.
- رابط الفيديو مابيتبعتش في قوائم المحاضرات، وبيتبعت بس بعد التأكد من الاشتراك والسنة.
- Audit Log لكل عملية إدارية (قسم «سجل العمليات»).

## حدود لازم تعرفها

- **يوتيوب Unlisted مش حماية حقيقية**: أي طالب معاه الرابط يقدر يشاركه. اللي معمول: الرابط مخفي لحد التحقق، علامة مائية متحركة باسم الطالب ورقمه، وحد الأجهزة. ده رادع مش حل نهائي. حقل `youtubeId` معزول في موديل `Lecture` عشان تنقل لـ Bunny/Vimeo بعدين من غير تغيير الداتا.
- تسجيل الشاشة مش ممكن منعه تقنياً في أي منصة ويب.
- الواجبات في المرحلة 1: وصف + رابط ملف + ميعاد. التسليم والتصحيح في المرحلة 2.

## النشر على Render

1. ارفع المشروع على GitHub.
2. أنشئ قاعدة بيانات MongoDB Atlas وانسخ الـ connection string. في Atlas > Network Access اسمح بالاتصال من Render.
3. في Render: New > Web Service (أو Blueprint من `render.yaml`)، الخطة **Starter** (الخطة المجانية بتنام).
4. الـ Environment Variables: `NODE_ENV=production`, `APP_URL=https://دومينك`, `MONGODB_URI`, `JWT_ACCESS_SECRET` (32+ حرف)، `BRAND_NAME`, `WHATSAPP_NUMBER`, `ADMIN_PHONE`, `ADMIN_PASSWORD`, `ADMIN_NAME`.
5. بعد أول نشر: من Shell في Render شغّل `npm run seed` مرة واحدة، وبعدها غيّر `ADMIN_PASSWORD` أو امسحه.
6. اربط الدومين من إعدادات Render. `APP_URL` لازم يطابق الدومين بالظبط (بيتستخدم في فحص CSRF).
7. لا تخزّن ملفات على قرص السيرفر (بتضيع مع كل نشر). رفع الـ PDF للملازم في المرحلة 2 هيبقى على Cloudinary أو R2.

## هيكل المشروع

```

src/config/                الإعدادات، السنين، الصلاحيات
src/models/                User, Session, Teacher, Course, Lecture, Homework, Package, Subscription, AuditLog
src/middleware/            auth (مصادقة+RBAC)، security (rate limit + CSRF)، validate، error
src/routes/                auth, public, student, admin/*
src/scripts/seed.js        إنشاء السوبر أدمن والمدرسين التجريبيين
public/                    الواجهة (HTML/CSS/JS بدون build)
```
